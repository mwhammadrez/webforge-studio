## ابزار ۱ — «اکسترکتر سایت کامل»

### محتوا
- `HELP.txt` (36 B): فقط `URL:` و `MODE: full`.
- `website-source-extraction-prompt.fa.md` (27,257 B): پرامپت مستر ۱۵ بخشی برای ایجنت‌های ترمینال‌دار.

### ساختار پرامپت (واقعی)
نقش، ورودی‌ها (`URL`, `MODE`, `OUTPUT_DIR`, `AUTH`, `MAX_PAGES`, `MAX_SIZE`, `PERMISSION`)، ۱۲ قاعدهٔ غیرقابل‌نقض، فاز ۰ محیط، فاز ۱ پروفایل، فاز ۲ آینه (`mirror/`)، فاز ۳ اسنپ‌شات (SingleFile/Playwright)، فاز ۴ شبکه/HAR، فاز ۵ سیستم طراحی، فاز ۶ دارایی‌ها، فاز ۷ تحلیل CSS/JS، فاز ۸ `clean/`، فاز ۹ اعتبارسنجی، فاز ۱۰ گزارش. درخت تصمیم و Definition of Done هم دارد.

### نقاط قوت
- تفکیک `mirror/` خام از `clean/` بازنویسی‌شده — تصمیم درست.
- قواعد robots/ToS/مجوز، عدم دور زدن CAPTCHA/Cloudflare، عدم ذخیرهٔ secret.
- حالت‌های `full | mirror | design | code | assets` و fallback برای سایت‌های SPA/بلاک‌شده.
- گزارش صادقانه از چیزهایی که استخراج نشده‌اند.
- خروجی ساخت‌یافته (design-system، HAR، گزارش) برای طراح.

### نقاط ضعف / ریسک
- **کد اجرایی ندارد**؛ یک دستورالعمل برای ایجنت است. بدون ایجنت + ابزارهای خارجی (wget/HTTrack/Playwright/SingleFile) کاری انجام نمی‌دهد.
- به ابزارهای GPL مثل HTTrack/wget وابسته است؛ توزیع تجاری نیاز به بررسی مجوز دارد.
- محدودیت‌ها (rate limit، max size، SSRF) در متن توصیه شده‌اند، نه در کد enforce.
- مجوز فایل مشخص نیست؛ محتوای آموزشی است.
- ریسک اخلاقی/حقوقی کپی کامل طراحی سایت ثالث را فقط با متن هشدار داده، نه با کنترل فنی.

### چه چیزی وارد برنامه شد
`ExtractionService` همان اصول را به‌صورت اجرایی پیاده می‌کند:
- `mirror/` + `clean/` + `reports/extraction-report.json` + `webforge.manifest.json`
- SSRF واقعی روی هر hop، robots.txt، محدودیت فایل/حجم/عمق/زمان، لغو، هشدار
- کشف CSS تودرتو، srcset، فونت، ویدیو، iframe
- حالت رندرشده با Chromium و عدم اجرای JS دانلودشده
- گزارش صادقانهٔ skipped/failed

**نتیجه:** ابزار ۱ به‌عنوان «روش‌شناسی» عالی است؛ به‌عنوان «نرم‌افزار» ناقص. جایگزین اجرایی ساخته شد.

## ابزار ۲ — «سازنده پنل ادمین»

### محتوا (واقعی)
- `admin.html` (23,960 B): پنل کامل با پیش‌نمایش iframe، تب همهٔ محتوا، آپلود، ذخیره.
- `site-editor.js` (10,541 B): موتور اجرا در صفحات؛ `content.json` را می‌خواند و overrides را اعمال می‌کند.
- `init_panel.py` (3,592 B): نصب‌کننده، اسکن صفحات، تزریق marker، ساخت `pages.json`.
- `serve.ps1` (5,998 B): سرور PowerShell + API.
- `run-panel.bat` (150 B).
- `README.fa.md` + `AGENT_PROMPT.md` با تست واقعی روی سایت ۲۶ صفحه‌ای.

### نقاط قوت
- مدل دادهٔ ساده و قابل‌برگشت: `content.json` تنها منبع تغییر؛ HTML بازنویسی نمی‌شود.
- تزریق idempotent با marker `gf-editor`.
- fallback selector با حذف لایه و متن قبلی؛ تلاش مجدد در چند بازهٔ زمانی.
- API ساده (`/api/content`, `/api/upload`) و سقف حجم.
- پنل واقعاً کار می‌کند و روی خروجی استخراج تست شده.

### نقاط ضعف / ریسک
- `serve.ps1` فقط ویندوز/PowerShell؛ روی لینوکس/مک کار نمی‌کند.
- بدون احراز هویت؛ فقط باید روی 127.0.0.1 اجرا شود.
- انتخاب‌گر CSS در DOM پویا شکننده است.
- افزودن عنصر جدید، background-image و متن‌های تودرتو را پشتیبانی نمی‌کند.
- آپلود بدون بررسی محتوای واقعی فایل (فقط MIME سمت کاربر/سرور) در کد اصلی.
- `__pycache__` و فایل‌های اجرایی در آرشیو هستند (بهداشت بسته پایین).

### چه چیزی وارد برنامه شد
- کیت در `resources/kits/admin-panel/` بسته‌بندی شد (`admin.html`, `site-editor.js`, `init_panel.py`).
- ابزار داخلی «سازنده پنل ادمین» همان مراحل init_panel را در TypeScript انجام می‌دهد: کپی، `pages.json`، تزریق marker، `content.json`.
- سرور پیش‌نمایش برنامه APIهای `/api/content` و `/api/upload` را با محدودیت ۸MB/۶۰MB و اعتبارسنجی MIME پیاده می‌کند؛ بنابراین پنل روی ویندوز و لینوکس کار می‌کند.
- E2E نصب پنل را روی سایت واقعی تأیید کرد.

**نتیجه:** ابزار ۲ واقعاً «کامل» است به‌جز سرور ویندوزی؛ با API داخلی به یک قابلیت cross-platform تبدیل شد.

## ابزار ۳ — «Full Site ready +.rar» (اسکیل‌ها)

### وضعیت دسترسی
- لینک: `https://gofile.io/d/XNf6yxva`
- فولدر شامل یک فایل: `Full Site ready +.rar` — ۱۱.۷MB — تاریخ ۲ نوامبر ۲۰۲۶.
- API عمومی Gofile با توکن مهمان: `{"status":"error-notPremium"}`.
- توکن پویا طبق الگوریتم `sha256(UA::language::accountToken::4hWindow::salt)` پیاده شد و **پذیرفته شد** (`error-rateLimit` به‌جای notPremium) — یعنی مسیر درست بود.
- سپس: `HTTP 429` پایدار، و در تلاش بعدی `SSL unexpected eof` / TLS reset از IP دیتاسنتر.
- صفحهٔ وب با مرورگر anti-detect باز شد و نام/حجم فایل دیده شد، اما دانلود به همان بلاک IP خورد.
- دانلود مستقیم از `store-*` بدون لینک فایل ممکن نبود.

### نتیجه
**محتوای آرشیو ممیزی نشد.** هیچ ادعایی دربارهٔ کیفیت یا کامل بودن آن نمی‌شود. برای پر کردن شکاف:
- `resources/skills/web-design/SKILL.md` (قواعد طراحی، ضد AI slop، جریان Spec-first)
- `resources/skills/extraction/SKILL.md`
- `resources/skills/site-qa/SKILL.md`
- جریان AI داخلی که این اسکیل را به پرامپت تزریق می‌کند.

اگر بعداً فایل را در دسترس قرار دهی، ادغام واقعی در گام بعدی انجام می‌شود.

## ابزار ۴ — تستر `https://gofile.io/d/gTBVKzYW`

- همان محدودیت‌ها: notPremium → rateLimit → TLS reset.
- نام فایل‌ها حتی دیده نشد چون صفحهٔ این فولدر در مرورگر کامل رندر نشد.
- **ممیزی انجام نشد.**

جایگزین بومی: `QaService` با Chromium داخلی و axe-core. پوشش فعلی: HTML، لینک، a11y (WCAG 2.2 AA)، SEO، کنسول، پرفورمنس، ریسپانسیو، امنیت پایه. گزارش JSON و امتیاز. در E2E روی سایت واقعی تست شد (امتیاز ۹۸ در نمونه).
